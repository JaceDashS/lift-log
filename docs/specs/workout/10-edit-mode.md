# Edit Mode Rules

## Purpose

이 문서는 `WorkOutTimer`의 편집 모드에서 요소 선택, 다중 선택, 해제, 시각 표시, 오버레이 상호작용이 어떻게 동작해야 하는지 정리한 기준 문서다.

대상 요소:

- `timer`
- `set`
- `total`
- `start` 버튼
- `set reset` 버튼
- `edit` 버튼
- `end` 버튼

텍스트 요소와 버튼 요소는 함께 선택될 수 있다.

## Core Principles

- `숏 프레스`와 `롱 프레스`의 역할은 다르다.
- `단일 선택`과 `다중 선택`의 시각 상태는 다르다.
- `주황색 강조`는 다중 선택 상태를 나타내는 표시다.
- 단일 선택은 리사이즈와 조작 대상 지정이 목적이다.
- 개발 모드와 오버레이 모드는 같은 편집 규칙을 사용해야 한다.

## Selection Rules

### Short Press

- 요소를 짧게 누르면 그 요소만 단일 선택된다.
- 숏 프레스는 항상 `단일 선택` 동작이다.
- 단일 선택 시에는 `선택 박스`와 `리사이즈 핸들`만 보여야 한다.
- 단일 선택만으로는 주황색 강조가 되지 않아야 한다.
- 이미 단일 선택된 요소를 다시 짧게 눌러도 선택은 유지된다.

### Long Press

- 요소를 길게 누르면 `다중 선택` 시작 동작으로 본다.
- 롱 프레스는 단일 선택이 아니라 다중 선택용 동작이다.
- 롱 프레스를 시작한 요소는 다중 선택 집합의 첫 요소가 된다.
- 롱 프레스를 시작하면 선택된 요소는 즉시 주황색 강조 상태가 된다.
- 롱 프레스 상태에서 손을 떼지 않고 다른 요소들 위로 이동하면 그 요소들도 선택 집합에 추가된다.
- 이 방식으로 버튼과 텍스트를 함께 선택할 수 있다.

### Multi Selection

- 선택된 요소가 2개 이상이면 다중 선택 상태다.
- 다중 선택 상태에서는 선택된 모든 요소가 주황색으로 강조된다.
- 다중 선택 상태에서도 선택 박스와 리사이즈 핸들은 `대표 선택 요소` 기준으로 보인다.

## Deselection Rules

### Blank Space Tap

- 클릭이 인식되었고 그 좌표가 어떤 선택 가능 요소 위도 아니면 현재 선택이 모두 해제된다.
- 이 빈공간 정의에는 편집 패널도 포함된다.
- 단일 선택 상태에서도 빈공간 탭으로 해제된다.
- 다중 선택 상태에서도 빈공간 탭으로 해제된다.

### Selected Element Tap

- 이미 선택된 요소를 다시 탭해도 선택은 해제되지 않는다.
- 단일 선택 상태에서 선택된 요소를 다시 눌러도 그대로 유지된다.
- 다중 선택 상태에서 선택된 요소 중 하나를 눌러도 다중 선택은 유지된다.

### Other Element Tap

- 다중 선택이 아닌 상태에서 다른 요소를 탭하면 그 요소가 새 단일 선택 대상이 된다.
- 다중 선택 상태에서 선택되지 않은 다른 요소를 탭하면 기존 다중 선택을 끝내고 새 단일 선택으로 전환한다.

우선순위:

1. 빈공간 탭은 항상 전체 해제다.
2. 선택된 요소 탭은 상태 유지다.
3. 선택되지 않은 다른 요소 탭은 새 단일 선택 전환이다.

## Visual Rules

### Single Selection Visuals

- 선택 박스 표시
- 리사이즈 핸들 표시
- 주황색 강조 없음

### Multi Selection Visuals

- 선택된 모든 요소에 주황색 강조 표시
- 버튼은 버튼 색이 주황색으로 바뀐다.
- `set`, `total`, `timer` 같은 텍스트 요소는 글자색이 주황색으로 바뀐다.

### Unselected Visuals

- 선택되지 않은 요소는 비선택 상태의 기본 색상과 기본 알파를 유지한다.
- 선택이 해제되면 모든 요소는 기본 상태로 돌아간다.

## Long Press Release

- 손가락을 떼는 순간 선택 집합은 유지되지만, 롱 프레스 진행용 내부 상태는 종료된다.
- 최종 선택 개수가 2개 이상이면 다중 선택 시각 상태를 유지한다.
- 최종 선택 개수가 1개면 단일 선택 상태로 처리한다.

## Overlay Interaction Rules

### Normal Overlay

- 편집 모드가 아닐 때 오버레이 전체는 뒤 화면으로 터치를 통과시켜야 한다.
- 이 상태에서는 뒤에 있는 앱과 상호작용할 수 있어야 한다.
- 대신 오버레이 제어는 기존 버튼 위치를 따라가는 별도 터치 가능한 버튼 창과 알림 액션으로 처리한다.

### Overlay Editing

- 편집 모드에 들어가면 오버레이 전체가 다시 터치를 받는다.
- 이 상태에서는 선택, 해제, 이동, 리사이즈, 회전, 편집 패널 조작이 모두 가능해야 한다.
- 편집 모드를 종료하면 다시 일반 오버레이 상태로 돌아가야 한다.

## Shared Mode Rules

- 개발 모드와 오버레이 편집 모드는 같은 선택, 해제, 이동, 리사이즈, 회전 규칙을 유지해야 한다.
- 편집 패널 값과 선택 규칙은 모드에 따라 달라지면 안 된다.
- 의도된 차이는 오버레이가 편집 모드 밖에서만 touch-through 라는 점뿐이다.

## Examples

### Example One

- `set`을 숏 프레스한다.
- 결과: `set`만 선택된다.
- 결과: 리사이즈 핸들이 보인다.
- 결과: 주황색은 아니다.

### Example Two

- `set`을 롱 프레스한 채로 `total`까지 드래그한다.
- 결과: `set`, `total`이 함께 선택된다.
- 결과: 두 요소는 주황색으로 보인다.

### Example Three

- `set`, `total`이 다중 선택된 상태에서 `set`을 탭한다.
- 결과: 다중 선택 유지
- 결과: 해제되지 않음

### Example Four

- `set`, `total`이 다중 선택된 상태에서 편집 패널 여백을 탭한다.
- 결과: 전체 선택 해제

### Example Five

- 일반 오버레이 상태에서 뒤에 있는 앱 버튼을 누른다.
- 결과: 뒤 앱 버튼이 눌려야 한다.
- 결과: 오버레이 제어는 작은 컨트롤 패널 또는 알림에서 한다.

## Document Scope

- 이 문서는 구현 세부사항 문서가 아니라 동작 규칙 문서다.
